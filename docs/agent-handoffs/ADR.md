# 架构决策记录：首页农历展示降级

## 状态

`verified`

## 背景

首页日历后端已经返回真实 `lunarLabel`，但 shadcn/ui `Calendar` 的公开 API 未暴露 `components/classNames` 扩展，内部 `DayButton` 固定，无法安全将农历注入每个日期格。股票趋势已按产品决策从首页移除，仅保留真实股票盈亏摘要。

## 约束

- 不修改 `node_modules`。
- 不在项目内实现平行日历。
- 不使用静态、模拟或前端猜算的农历数据。
- 保持 shadcn/ui UI 组件复用和当前 HMR 页面验证路径。

## 候选方案

### 方案 A：选中日期区展示农历（本轮采用）

- 优点：使用现有 shadcn/ui `Calendar`，不引入维护分叉；后端真实值可见；改动小、可回滚。
- 代价：未选中的日期格不显示农历。
- 风险：与“每个日期格显示农历”的理想体验有差距。

### 方案 B：shadcn/ui 上游扩展或受控 fork

- 优点：可在日期格内原生展示公历、农历和事件点。
- 代价：需要单独评估上游 API、fork 维护、发布和包体积影响。
- 风险：扩大本轮范围，可能引入组件兼容和升级成本。

## 决策

本轮采用方案 A：选中日期信息区展示后端真实 `lunarLabel`；`lunarLabel` 缺失时展示明确缺省态。首页本轮不实现每日日期格农历，不修改依赖包、不造平行日历；方案 B 单独作为后续技术任务。

## 原因

当前首页的核心交付是布局、行动顺序、空态和真实数据边界。方案 A 能闭合本轮实现与证据链，避免用不受支持的组件扩展方式制造不可维护的视觉补丁。

## 兼容性边界

- 日历仍使用 shadcn/ui `Calendar`。
- 后端 `calendar.days[].lunarLabel` 保持现有字段，不新增契约。
- 股票趋势不再属于首页范围；股票盈亏摘要继续消费真实持仓数据。
- 所有复核沿用当前 `5173` HMR 标签页，不新开 tab。

## 性能与观测

- 性能预算：不新增日历依赖、不修改 shadcn/ui 包、不扩大首页图表负载。
- 观测指标：构建成功、视图模型测试通过、1440/1024/375 浅深色截图、日历选中日期农历显示、股票趋势不存在。

## 迁移与回滚

- 迁移步骤：保留当前实现；将每日日期格农历需求登记为独立上游扩展/fork 任务。
- 回滚条件：选中日期农历显示引入回归，或真实接口字段语义变化。
- 回滚步骤：恢复到不显示农历摘要的版本，不触碰后端数据契约。
