# 产品需求文档：工作台首页三次设计

## 状态

`ready-for-implementation`

## 任务目标

将首页调整为每天打开即可获得上下文和下一步行动的个人工作台：以动态问候、多条可操作智能提示、待办/到期、股票盈亏可视化和经期预测形成每日节奏；日历仅作为紧凑展示组件，创作收件箱从首页移除。

## 用户与使用场景

### 目标用户

个人工作台使用者，需要在本机快速判断今天和近期应该处理什么。

### 触发场景

每天打开首页、刷新数据、查看某一天的安排，或在事项临近/逾期时快速进入对应模块。

### 用户当前痛点

- 旧首页首屏被孤立指标卡和图表占据，缺少时间感与下一步引导。
- 日历承担了过多空间，但农历日期格受 shadcn/ui 扩展能力限制，无法作为本轮核心体验。
- 待办/到期事项的纵向时间顺序和完整入口不够明确。
- 股票区域应以盈亏为主，原趋势图表达不够直观且缺少可靠历史点位。
- 首页缺少经期预测和针对不同事项的个性化提示动作。

## 已知事实

- 当前首页入口为 `packages/shell/src/App.jsx` 的 `DashboardPage`。
- 后端已通过 `lunar-javascript` 生成 `lunarLabel`，但 shadcn/ui `Calendar` 无安全的公开日期格扩展；本轮日历只做紧凑展示，农历日期格另立上游扩展任务。
- 当前选中日期时间线已有纵向排序逻辑；全局“即将到期”仍需显式按 `dueAt/dueDate` 排序并提供完整列表入口。
- 股票趋势图已从首页移除；首页保留真实持仓市值/盈亏摘要和盈亏可视化。
- 经期模块已有周期与预测相关数据能力，首页需复用真实数据，不重复计算一套来源。
- 当前 HMR 页面为 `http://127.0.0.1:5173/`，后续复核沿用同一标签页。

## 业务假设

- 智能提示优先采用可解释规则，不把静态统计包装成 AI。
- 提示优先级：逾期事项 → 今日到期 → 经期预测/阶段提醒（仅在真实数据且用户已配置时）→ 股票盈亏异常 → 特殊日子 → 最近待办；每条提示必须有来源、原因和一个真实动作。
- 经期信息属于敏感个人信息；无数据、未配置或计算不可靠时不展示推断性提示。
- 日历是辅助展示，不再为每日日期格农历阻塞首页交付。

## 范围

### 必须完成

- 顶部保留动态日期/问候和多条智能提示入口，不再使用“今天，先处理重要的事” Hero 文案块。
- 1440 使用主提示区 + 待办/到期/盈亏/经期的工作台网格；1024 改为上下两段；375 按“提示 → 待办/到期 → 盈亏 → 经期预测 → 紧凑日历”单列。
- 日历改为小尺寸展示组件，不占据主要首屏空间；农历作为后续扩展，不阻塞本轮。
- 待办/到期按 `Asia/Shanghai` 时间从上到下排列；无具体时间的事项标记“待安排”；超出展示上限提供“查看全部”入口。
- 智能提示支持多条轮播或展开查看；动效仅用于进入、切换和状态反馈，不使用持续闪烁或干扰阅读的动画；必须支持键盘和 reduced-motion。
- 首页移除创作收件箱和股票趋势图；保留真实持仓盈亏可视化，优先选择能表达总盈亏、盈亏比例和正负状态的 shadcn/ui/现有 Chart 方案。
- 新增经期预测摘要：展示预测日期/阶段、预测依据和进入经期页面的单一动作；数据不足时展示安全空态。
- 所有新增或调整的 UI 优先使用 shadcn/ui 组件，不手写平行组件。

### 明确不做

- 不使用静态、模拟或猜测的农历、股票盈亏、经期预测和个性化数据。
- 不在项目内实现平行日历；每日日期格农历另立 shadcn/ui 上游扩展/fork 任务。
- 不新增未经确认的后端契约；优先复用现有周期、持仓、待办和到期数据来源。
- 不以“组件渲染成功”代替视觉验收；不在旧 `dist` 产物上截图。
- 不在本轮顺手处理 shadcn/ui 图标包动态导入和约 4MB 主 bundle 风险，除非单独建立性能任务。

## 验收标准

- [ ] 1440/1024/375 下无横向溢出，布局符合对应断点。
- [ ] 首屏智能提示支持多条可解释提示，每条有来源、原因和一个真实动作；动效不影响阅读、键盘操作和 reduced-motion。
- [ ] 日历为紧凑展示组件，不占据主要首屏空间，且无异常空白。
- [ ] 待办/到期纵向排序、缺省时间和“查看全部”入口可验收。
- [ ] 首页不存在创作收件箱和股票趋势图；盈亏可视化使用真实持仓数据，突出总盈亏、比例和正负状态，缺失时显示结构化空态。
- [ ] 经期预测使用真实周期数据；数据不足时不推断，并提供进入经期页面的入口。
- [ ] 浅色/深色主题下语义色、对比度和 focus ring 可用。
- [ ] 提交真实接口数据、构建结果、1440/1024/375 浅深色截图和关键交互实测证据。

## 指标

- 基线：当前首页已有基础提示、待办/到期和盈亏摘要，但日历占比过大，缺少经期预测，智能提示能力单一。
- 目标：用户无需滚动即可看到可执行提示、核心行动、盈亏状态和经期预测；空态不误导，动效不干扰。
- 观察周期：实现后进行一次设计复核和一次回归复核。

## 风险与未决问题

- 经期预测涉及敏感健康信息，需要明确用户已配置数据和安全空态。
- 盈亏图表需确认使用 shadcn/ui `Sparkline` 还是现有 `Chart`，但不得回退到模拟历史点位。
- 多提示轮播需防止自动切换导致信息遗漏，默认应允许手动查看全部提示。
