## 最新视觉复核：顶部三栏节奏

- 最新截图显示顶部三栏关系已成立，但月视图日历卡高度约 400px，明显高于智能提示和股票盈亏卡，导致第一行下方出现大面积断层。
- 当前结果不符合“日历是紧凑小组件”的目标，视觉结论仍为 `blocked`。
- 修复方向：优先确认 shadcn/ui 原生 `Calendar` 是否能在公开 API 内安全呈现当前周 7 天；若不能，禁止通过固定高度、`overflow` 裁剪或空白填充伪造紧凑效果，应改为受支持的紧凑展示形态或另立组件能力评估。
- 验收重点：提示/股票/日历首行高度节奏接近，第二行紧接出现；不能只证明三栏存在或 `overflow=0`。

## r9 复核补充：日期基准一致性

- 当前源码中顶栏问候使用浏览器本地 `new Date()`，7 日展示条/日历逻辑使用 `calendarDateKey` 的 `Asia/Shanghai` 转换；两者没有共享同一日期基准。
- 在跨时区、固定测试时间或日期临界点，可能出现顶栏日期与日历周范围不一致，用户会误判当前周。
- 修复验收：顶栏日期、7 日条起止日期、选中态和事件过滤必须统一使用 `Asia/Shanghai`；周起始规则必须固定并有回归测试，不能只依赖浏览器本地时区。
- 当前视觉结论继续为 `blocked`，需重新提交 scrollY=0 顶部证据及覆盖日历/行动/经期的完整或分段截图。
