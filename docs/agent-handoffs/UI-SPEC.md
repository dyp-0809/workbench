## 设计判断

### 主视觉方向

“每日行动面板”，不是数据模块汇总页。用户打开首页后应在首屏获得三个答案：今天是什么日期、最应该先做什么、接下来有哪些安排；日历只作为轻量时间参照，不再承担农历编辑或大面积日程展示。

### 页面主焦点

智能提示是首屏唯一主视觉；紧凑日历和纵向时间线提供时间上下文；待办/到期、经期预测与股票盈亏是可执行的次级信息；创作收件箱删除，股票不展示历史趋势，避免所有卡片同时争抢焦点。

### 借鉴的成熟方案

采用 Appica 的克制留白、语义色、清晰标题基线和现有组件层级；借鉴个人生产力面板的“单一下一步 + 时间轴”模式，拒绝四张环图指标墙、渐变装饰、无意义的大块留白和把静态统计包装成 AI。

## 页面结构

### 网格与容器

- 顶栏：页面已有顶栏，保留真实本地日期/问候、刷新和生成明日内容；不再创建 Hero，不显示“今天，先处理重要的事”。
- 1440：主内容使用 12 列网格，间距使用现有 Appica/项目 spacing token；第一屏以智能提示为主，紧凑日历与纵向行动区并列，右侧放经期预测与股票盈亏摘要。
- 1024：改为上下两段，不硬挤 8/4；提示和行动优先，日历作为小组件随后出现。
- 375：严格单列，顺序为提示 → 待办/到期 → 经期预测 → 股票盈亏 → 紧凑日历；侧栏仅保留图标，文字不得逐字折行。
- 日历作为纯展示小组件，使用 Appica `Calendar size="sm"`，不显示农历、不显示大块时间线、不用固定最小高度；在标题和日期网格之间保持紧凑连续节奏，选中日期只更新轻量日期摘要。

### 信息层级

- P0：动态日期/问候、智能提示流中的当前下一步、第一批待办/到期行动。
- P1：经期预测（仅在隐私开启且有真实数据时）、股票总盈亏与盈亏比例、日历当前日期。
- P2：数据来源状态、完整行动列表入口。
- P3：非紧急统计；本轮不展示创作收件箱和股票历史趋势。

## 设计令牌

### 色彩角色

- 背景、卡片、正文、弱化文本、边界、主操作、成功、警告、危险和 focus ring：全部使用项目现有 Appica 语义 token。
- 逾期使用 error，临近到期使用 warning，正常盈亏使用 success，缺省/信息使用 info；不得新增渐变背景或硬编码色值。
- 浅色与深色必须保持文本对比度、边界可见性和 focus ring 可识别；颜色不能成为唯一的信息编码方式。

### 字体与排版

- 沿用项目现有系统/CJK 字体，不新增字体依赖。
- 标题使用现有页面标题层级；卡片统一“标题行 → 主信息 → 说明 → 单一动作”。
- 正文不得小于项目现有可读字号；弱化说明保持清晰对比。
- CJK 长标题允许自然换行，列表标题最多两行，不能通过固定宽度压成竖排或产生横向滚动。

### 形状与层次

- 沿用 Appica `Card` 的现有圆角、边框和阴影，不自制卡片体系。
- 右侧卡片通过内部 padding、标题基线和列表节奏对齐，不使用固定高度填白；股票只保留当前市值/盈亏摘要，不再展示股票趋势图。
- 动效仅使用已有组件状态和短暂的状态反馈；支持 `prefers-reduced-motion`，不做装饰性入场动画。

### 数字动效

- 金额、盈亏、数量、计数、时间和日期等数字在首次进入或真实值变化时使用滚动/位移过渡；静止数字不循环播放，避免首页持续闪烁。
- 智能提示标题使用 Appica `TextAnimate`；真实目标时间的剩余时长使用 Appica `Countdown`，不把 `Countdown` 用来推算当前时钟或农历。
- 当前时分秒与农历只消费真实数据；数字动效必须保留屏幕阅读器可读文本，`prefers-reduced-motion` 下直接显示最终值。

## 组件规则

- 优先复用 Appica `Card`、`Badge`、`Button`、`Calendar`、`Chart`、`Empty`、`LoadingButton`，不手写平行组件。
- 智能提示：一个 `Card`，只显示一条最高优先级提示；内容为标题、`reason`、来源 Badge 和 `action` 按钮，多条信息只能进入可展开的来源/数据状态区。
- 日历：作为纯展示小组件使用 Appica `Calendar size="sm"`，日期格只显示公历日，不显示农历；真实 `lunarLabel` 不在本轮首页渲染，后续由独立 Appica 上游扩展任务处理。
- 时间线：纵向排列待办/到期事件，按 `Asia/Shanghai` 的 `dueAt → time → dueDate` 排序；缺少具体时间显示“待安排”，支持长标题换行。
- 待办/到期：每行一个真实动作；待办可完成/重新打开，到期可查看；超过展示上限提供“查看全部”。
- 股票：只保留真实持仓的当前市值、持仓盈亏、盈亏比例和“查看仓位”入口；视觉采用单次快照的 Appica `Chart` 横向对比条（成本总额 vs 当前市值）或等价非时间序列表达，不使用 `stockHistory.points` 趋势图、静态点位或模拟数据。
- 经期预测：仅在 `privacy.menstrualEnabled=true` 且后端返回真实预测字段时展示阶段/预测日期范围和“查看健康”入口；关闭、未设置、数据不足或失败时不展示经期详情，不进行前端推断。
- 智能提示流：可在同一 Appica `Card` 内切换/展开多条已确认提示，但同一时刻只突出一条；每条包含来源 Badge、reason 和一个真实 action，切换使用轻量淡入/位移动效，支持键盘操作和 reduced-motion。
- 空态：使用 Appica `Empty`，必须带对应模块入口；“暂无数据”“尚未设置”“暂时不可用”三种语义不得混用。
- 移动侧栏：现有 Appica 导航组件保留，窄屏隐藏文字而非压缩折行，图标按钮保留可访问名称/tooltip。

## 数据与状态表现

- 正常：真实接口字段驱动，提示仅来自已确认规则，不额外假装接入 AI。
- 空：没有触发条件时提示“今天没有需要优先处理的事项”；没有持仓时显示股票摘要空态；日历作为纯展示组件不增加农历空态。
- 尚未设置：数据源 `configured: false` 时显示“尚未设置”，提供进入配置/对应模块的入口，不写成“暂无异常”。
- 加载：保留 Appica `Card` 骨架/加载文案，避免布局跳动；不展示猜测数字或假点位。
- 错误：显示真实原因或“个性化提示暂时不可用”，提供“重试”；错误不阻断日历和其他已成功加载模块。
- 长文本：标题最多两行后省略并提供完整 tooltip/可访问名称；CJK 不得出现逐字竖排。
- 极端数值：股票盈亏支持负号、百分比和大数格式；不因数值长度撑破卡片，必要时换行或缩略并保留完整可读信息。

## 响应式策略

- 桌面 1440：12 列满幅；智能提示主卡与行动区优先，紧凑日历作为小组件，不留无意义垂直空白。
- 平板 1024：上下两段；提示和行动优先，日历作为紧凑小组件随后出现；不将 8/4 硬缩成拥挤窄栏。
- 窄屏 375：单列顺序为提示 → 待办/到期 → 经期预测 → 股票盈亏 → 紧凑日历；侧栏仅图标，页面和卡片 `scrollWidth === clientWidth`；按钮可换行但不可溢出。
- 主题：浅色/深色均检查 Card 边界、弱化文本、Badge、错误/警告/成功色和键盘 focus ring。
- 热更新：沿用当前 `5173` HMR 标签页，不重复打开新 tab；截图必须来自最新 bundle。
